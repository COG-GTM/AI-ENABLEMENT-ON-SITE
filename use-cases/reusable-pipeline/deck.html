Why 'convert this entire repo' fails

  • The whole tree is handed to the agent on every step: context and tokens run out
  • Nothing is left behind for a second engineer, a second program, or a CI job
  • 'Done' is a sentence in a transcript, not a file with evidence
  • Needed: a pipeline the team owns in its repository, bounded per unit, resumable, honest about proof

Controlling context and tokens

  • Scan once; every later step reads dependency-map.json and one pack, never the tree
  • One pack per unit with a budget: source, dependency excerpts, callers, open questions, result contract
  • Over budget: dependency excerpts shrink first, then source is truncated, and the pack says so
  • Leaf-first order: callers' packs point at finished work instead of carrying it
  • manifest.json shows bytes and tokens per pack before anything runs; choose --limit from it
  • Results persist in results/<id>/; the next unit reads files, not a transcript
  • Resume, do not restart: unchanged stages are skipped, done / blocked results survive

What Devin adds, and where the offline path stops

Devin adds

  • AGENTS.md and skills read automatically per repository
  • CLI in the IDE against the working tree; Plan mode and least-privilege defaults
  • The same skill runs on the next program without re-explaining the method
  • Discovery, packing, compare, and report are plain Python: no agent required to run them

Honest limits

  • Agent execution needs the Cognition backend; unattended runs need a runner with that access
  • The golden path is a dry run: it proves the glue and the journal, not a migration
  • 'done' is a claim; 'proven' needs a comparison or the evidence files
  • No tool ever moves a backlog item to closed
