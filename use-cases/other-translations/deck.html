Ada to C++

What makes it hard

  • Ranges, subtypes, discriminated records; generics; representation clauses
  • Tasking and protected objects; interrupt handlers
  • SPARK contracts and certification evidence tied to the original

Landscape and realistic first step

  • libadalang / GNAT parse Ada from Python; GNAT Pro CCG generates C as a product; no maintained OSS Ada-to-C++ translator
  • Scanner: with / use, spec vs body, tasks, protected types, generics, pragmas, Interfaces.C
  • Tasking, rep clauses, interrupt handlers -> retain / wrap first; proof per subprogram on vectors

Fortran modernisation

What makes it hard

  • Fixed-form F77: COMMON, EQUIVALENCE, computed GOTO, implicit typing
  • COMMON makes dependencies a data-flow problem, not a call graph
  • Numerics: precision, evaluation order, compiler flags define 'equivalent'

Landscape and realistic first step

  • fparser, LFortran (AST / ASR), fable / cctbx (F77 to C++); f2py wraps instead of translating - often step one
  • Scanner: program units, CALL graph, COMMON and MODULE membership, INCLUDE, implicit typing, GOTO, I/O units
  • COMMON- and I/O-heavy units wrap first; numerical kernels port; tolerance per column in bench_compare.py
