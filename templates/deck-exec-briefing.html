What Devin with this repository adds over a general coding agent

A general agent on the same tree

  • Reads what fits in one prompt and re-reads the tree every session
  • Writes code that looks right; the proof is whatever you remember to ask for
  • Blurs the boundary: a reading of a diagram presented as behaviour
  • One-off session; nothing for the next person to rerun

This repository with Devin

  • The scanner reads the whole tree once; each unit gets one bounded prompt
  • Every lane ends in bench_compare.py or make test saying PASS or FAIL per column
  • Skills print what is not proven, in their own output, every run
  • Skills, tracker, backlog and deck rebuild offline from plain CSV and JSON anyone can open

What is not covered, said before you ask

  • No .vi to Python converter: a VI is a proprietary binary; lvkit gives inventory and drawings, never the deliverable
  • No C to Python converter: the Python twin is a second implementation kept honest by shared tests
  • Host tests do not prove target timing, interrupts, RTOS scheduling, DMA, power modes, MISRA or DO-178C objectives
  • Vector equivalence does not prove the design, only that the code matches the model on those rows
  • Without a recording a LabVIEW port is a draft, and the skill labels it as one
  • Repo-scale MATLAB and C scanners, the prompt pack and the pipeline runner are designed, not merged
  • No TestStand or TDMS file ships here; the real-VI lane stops at the diagram reading until someone records a run

Day one on your tree: the commands

  • python tools/doctor.py (is this laptop ready? prints READY)
  • python tools/golden_path.py (every workflow end to end, offline; proof left in outputs/golden/)
  • python tools/vi_fleet_scan.py <your tree> --name <estate> (inventory CSV + migration backlog)
  • /labview-to-python <rig export or .vi> <recording.csv> (one rig, proven against its recording)
  • /bring-your-firmware <your C tree> (map, host harness, first three tests)
  • /matlab-to-code <model.m> --target both (notes, vectors, Python + C, comparison)
  • python tools/tracker_report.py --file outputs/<estate>-migration-backlog.json (the status report)
Then: /track-and-report and /exec-deck read those files; ask for the end result and Devin runs the whole row (WORKFLOWS.md).
