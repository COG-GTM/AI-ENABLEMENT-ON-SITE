# Engagement Charter

## Intent

Provide a safe, repeatable, and practical introduction to AI-assisted software engineering using only approved Federal capabilities. Demonstrations should show how a human directs, reviews, and validates Devin Desktop and Devin CLI rather than presenting autonomous execution as a substitute for engineering judgment.

## Objectives

- Establish the operating and data boundary before any demonstration.
- Demonstrate end-to-end workflows that begin with a clear task and end with reviewed evidence.
- Compare Desktop and CLI interaction patterns without overstating feature parity.
- Discover high-value use cases and the constraints that affect adoption.
- Capture reusable decisions, action items, and success measures without identifying content.

## Non-goals

- Production deployment or production data access
- Broad filesystem, network, repository, or integration access
- Security testing against a live system
- Procurement, authorization, accreditation, or legal approval
- Unreviewed code changes or external publication
- Commitments about features, controls, or integrations that have not been verified

## Exit criteria

- Readiness and boundary checks are complete.
- Selected demonstrations have synthetic inputs and a tested fallback.
- Participants can explain the plan-review-verify workflow.
- Candidate use cases are prioritized by value, feasibility, risk, and evidence.
- Decisions and follow-up actions are recorded in sanitized form.
- No prohibited data or identifying information enters the repository or agent context.
