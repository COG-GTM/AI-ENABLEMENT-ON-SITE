# ADR-0001: Moving-average filter instead of IIR low-pass

- Status: Accepted
- Date: synthetic
- Relates to: SN-REQ-003, SN-REQ-021, SN-REQ-023

## Context

IMU samples at 100 Hz carry vibration noise above ~10 Hz. The uplink is 1 Hz, so only a smoothed
value is needed. The MCU has no hardware FPU and the loop budget is 8 ms (SN-REQ-021).

## Decision

Use a 4-sample integer moving average per axis (`src/filter.c`).

## Alternatives considered

| Option | Pros | Cons |
| --- | --- | --- |
| 4-sample moving average (chosen) | Integer-only, 4 adds + 1 divide per axis, trivially testable, no allocation | Weak roll-off (about -3 dB at 11 Hz), 30 ms group delay |
| 1st-order IIR (alpha = 1/8) | Fewer stores, smoother tail | Fixed-point scaling pitfalls; harder to explain in review |
| 2nd-order Butterworth (biquad) | Sharp roll-off | Needs Q15 arithmetic or float; more test surface for a small gain |

## Consequences

- Filter warm-up: the first 3 samples after reset are averages of fewer samples (tested).
- If a stricter cutoff is required later, replace `filter.c` behind the same `filter_update` API
  and keep `tests/test_filter.py` as the acceptance gate.
